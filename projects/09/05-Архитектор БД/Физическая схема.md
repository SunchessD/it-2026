# Физическая схема

Целевая СУБД — PostgreSQL 17. Схему создаёт [sql/01_create_database.sql](sql/01_create_database.sql), а не миграции веб-фреймворка. Идентификаторы — `bigint`, создаваемые `GENERATED BY DEFAULT AS IDENTITY`. Время хранится как `timestamptz`. Деньги в предметной области нет.

Redis 7 не дублирует эти таблицы. Его ключи описаны в [логической схеме](Логическая%20схема.md) и в [описании БД](Описание%20БД.md).

Имена в базе — коды. В интерфейсе им соответствуют русские подписи.

| Код | Подпись |
| --- | --- |
| `organization_admin` | администратор организации |
| `analyst` | аналитик |
| `product` / `service` | товар / услуга |
| `positive` / `neutral` / `negative` | позитивная / нейтральная / негативная |
| `negativity` / `spam` | негатив / спам |
| `open` / `confirmed` / `false_positive` | открыта / подтверждена / ложная |
| `accepted` / `processing` / `ready` / `failed` | принята / обрабатывается / готова / не завершена |

## `organization`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `organization_id` | bigint | PK, IDENTITY |
| `name` | varchar(200) | NOT NULL, CHECK: не пустое после обрезки пробелов и совпадает с `btrim(name)` |
| `data_revision` | bigint | NOT NULL, DEFAULT 0, CHECK `>= 0` |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |

`data_revision` увеличивает приложение в той же транзакции, что и обработка партии до `ready`, переименование объекта или источника и смена статуса разбора. Выражение — `data_revision = data_revision + 1`. Читать значение в Python и записывать сумму нельзя.

## `account`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `account_id` | bigint | PK, IDENTITY |
| `organization_id` | bigint | NOT NULL, FK → `organization`, ON DELETE RESTRICT |
| `full_name` | varchar(200) | NOT NULL, тот же CHECK, что у названия организации |
| `email` | varchar(320) | NOT NULL, CHECK: содержит `@` и не имеет крайних пробелов |
| `password_hash` | varchar(255) | NOT NULL |
| `role` | varchar(32) | NOT NULL, CHECK `IN ('organization_admin', 'analyst')` |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |

Уникальный индекс `account_email_lower_uq` по `lower(email)`. Пароль в открытом виде не хранится. Хэш считает API: Argon2id, у каждой записи своя соль. Одинаковые пароли не дают одинаковую строку `password_hash`. Смена пароля записывает новый хэш только после верного кода из письма. Код и ожидающий хэш держатся в Redis `pwd:{account_id}` и в PostgreSQL не хранятся. Присоединение по коду своей организации ставит `role = analyst` и не меняет `organization_id`.

Удаление организации с участниками через интерфейс не предусмотрено, поэтому внешний ключ — `RESTRICT`.

## `invitation`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `invitation_id` | bigint | PK, IDENTITY |
| `organization_id` | bigint | NOT NULL, FK → `organization`, ON DELETE RESTRICT |
| `code` | varchar(64) | NOT NULL, UNIQUE |
| `revoked` | boolean | NOT NULL, DEFAULT false |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |

Код — случайные 32 байта в кодировке base64url. Его показывает администратор, поэтому это не хэш. Отзыв ставит `revoked = true` и не удаляет строку.

## `monitored_object`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `object_id` | bigint | PK, IDENTITY |
| `organization_id` | bigint | NOT NULL, FK → `organization`, ON DELETE RESTRICT |
| `name` | varchar(200) | NOT NULL, CHECK непустого названия |
| `object_type` | varchar(16) | NOT NULL, CHECK `IN ('product', 'service')` |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |
| `updated_at` | timestamptz | NOT NULL, DEFAULT `now()` |

`UNIQUE (object_id, organization_id)` — цель составных внешних ключей источника и аномалии. `updated_at` обновляет API. `DEFAULT now()` само по себе при `UPDATE` колонку не меняет.

## `source`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `source_id` | bigint | PK, IDENTITY |
| `object_id` | bigint | NOT NULL |
| `organization_id` | bigint | NOT NULL |
| `platform_name` | varchar(200) | NOT NULL, CHECK непустого названия |
| `card_url` | varchar(2000) | NOT NULL, CHECK: начинается с `https://` и не содержит пробелов |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |
| `updated_at` | timestamptz | NOT NULL, DEFAULT `now()` |

Составной FK `(object_id, organization_id)` → `monitored_object (object_id, organization_id)` ON DELETE RESTRICT. `UNIQUE (source_id, organization_id, object_id)` нужен отзывам. Ссылка хранится как адрес карточки. Сервер по ней отзывы не забирает.

## `anomaly_threshold`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `organization_id` | bigint | PK, FK → `organization`, ON DELETE RESTRICT |
| `negativity_limit` | numeric(8,2) | NOT NULL, CHECK `BETWEEN 1 AND 100` |
| `spam_limit` | numeric(8,2) | NOT NULL, CHECK `BETWEEN 1 AND 100` |
| `version` | bigint | NOT NULL, DEFAULT 0, CHECK `>= 0` |
| `updated_at` | timestamptz | NOT NULL, DEFAULT `now()` |
| `updated_by` | bigint | NULL, FK → `account`, ON DELETE RESTRICT |

Строка создаётся в транзакции регистрации со значениями 2.00 и 2.00. Предел — множитель доли окна к доле базового периода. `updated_by` у начальной строки пустой.

## `import_batch`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `import_id` | bigint | PK, IDENTITY |
| `source_id` | bigint | NOT NULL |
| `organization_id` | bigint | NOT NULL |
| `status` | varchar(16) | NOT NULL, CHECK `IN ('accepted', 'processing', 'ready', 'failed')` |
| `accepted_count` | integer | NOT NULL, CHECK `>= 0` |
| `undated_count` | integer | NOT NULL, CHECK `>= 0 AND undated_count <= accepted_count` |
| `failure_reason` | varchar(500) | NULL |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |
| `started_at` | timestamptz | NULL |
| `finished_at` | timestamptz | NULL |

Составной FK `(source_id, organization_id)` проверяется через уникальность `(source_id, organization_id)` на источнике. Дополнительно `UNIQUE (import_id, organization_id, source_id)`.

CHECK: `failed` требует `failure_reason`, остальные статусы держат его пустым. `ready` и `failed` требуют `finished_at`. `processing`, `ready` и `failed` требуют `started_at`.

Файл целиком либо принимается, либо не создаёт партию. Обрыв транзакции обработки не ставит `failed` и не оставляет зафиксированный `processing`: партия остаётся `accepted`. Если обработка завершилась без тональности, та же транзакция фиксируется как `failed`: заполнены `failure_reason`, `started_at` и `finished_at`. Ранее готовые партии не меняются, `data_revision` не растёт.

## `review`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `review_id` | bigint | PK, IDENTITY |
| `import_id` | bigint | NOT NULL |
| `source_id` | bigint | NOT NULL |
| `object_id` | bigint | NOT NULL |
| `organization_id` | bigint | NOT NULL |
| `body` | text | NOT NULL, CHECK `char_length(btrim(body)) > 0` |
| `reviewed_at` | timestamptz | NULL |
| `sentiment` | varchar(16) | NULL, CHECK `IN ('positive', 'neutral', 'negative')` |
| `spam` | boolean | NULL |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |

Составной FK `(import_id, organization_id, source_id)` → `import_batch`. Составной FK `(source_id, organization_id, object_id)` → `source`. `UNIQUE (review_id, organization_id, object_id)` — цель связи с аномалией.

CHECK `spam IS NULL OR reviewed_at IS NOT NULL`: пометка спама не ставится отзыву без даты. `created_at` — время приёма строки, оно не подменяет `reviewed_at`.

Индексы:

- `review_dashboard_idx (organization_id, object_id, reviewed_at)` WHERE `sentiment IS NOT NULL` — сводка и динамика;
- `review_feed_idx (organization_id, source_id, sentiment, reviewed_at DESC, review_id DESC)` — лента;
- `review_object_time_idx (object_id, reviewed_at)` WHERE `reviewed_at IS NOT NULL` — окно и базовый период.

## `anomaly`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `anomaly_id` | bigint | PK, IDENTITY |
| `object_id` | bigint | NOT NULL |
| `organization_id` | bigint | NOT NULL |
| `anomaly_type` | varchar(16) | NOT NULL, CHECK `IN ('negativity', 'spam')` |
| `status` | varchar(16) | NOT NULL, DEFAULT `open`, CHECK `IN ('open', 'confirmed', 'false_positive')` |
| `window_start` | timestamptz | NOT NULL |
| `window_end` | timestamptz | NOT NULL, CHECK `window_start < window_end` |
| `baseline_start` | timestamptz | NOT NULL |
| `baseline_end` | timestamptz | NOT NULL, CHECK `baseline_start < baseline_end AND baseline_end = window_start` |
| `window_total` | integer | NOT NULL, CHECK `>= 5` |
| `window_marked` | integer | NOT NULL, CHECK `BETWEEN 0 AND window_total` |
| `baseline_total` | integer | NOT NULL, CHECK `>= 5` |
| `baseline_marked` | integer | NOT NULL, CHECK `BETWEEN 0 AND baseline_total` |
| `window_rate` | numeric(8,6) | NOT NULL, CHECK `BETWEEN 0 AND 1` |
| `baseline_rate` | numeric(8,6) | NOT NULL, CHECK `BETWEEN 0 AND 1` |
| `version` | bigint | NOT NULL, DEFAULT 0, CHECK `>= 0` |
| `opened_at` | timestamptz | NOT NULL, DEFAULT `now()` |
| `resolved_at` | timestamptz | NULL |
| `resolved_by` | bigint | NULL, FK → `account`, ON DELETE RESTRICT |

Составной FK `(object_id, organization_id)` → `monitored_object`. `UNIQUE (anomaly_id, organization_id, object_id)`. `UNIQUE (object_id, anomaly_type, window_start, window_end)` не даёт открыть вторую такую же аномалию.

CHECK: статус `open` держит `resolved_at` и `resolved_by` пустыми; `confirmed` и `false_positive` заполняют оба. Показатели — снимок. Позже их не пересчитывают из-за смены порогов.

Индекс `anomaly_org_idx (organization_id, opened_at DESC, anomaly_id DESC)`.

## `anomaly_review`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `anomaly_id` | bigint | PK, часть составного FK |
| `review_id` | bigint | PK, часть составного FK |
| `organization_id` | bigint | NOT NULL |
| `object_id` | bigint | NOT NULL |

FK `(anomaly_id, organization_id, object_id)` → `anomaly`. FK `(review_id, organization_id, object_id)` → `review`. Оба ON DELETE RESTRICT. Составной первичный ключ не позволяет включить отзыв в ту же аномалию дважды.

## `notification`

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `notification_id` | bigint | PK, IDENTITY |
| `anomaly_id` | bigint | NOT NULL |
| `organization_id` | bigint | NOT NULL |
| `message` | varchar(500) | NOT NULL, CHECK непустого текста |
| `created_at` | timestamptz | NOT NULL, DEFAULT `now()` |

FK `(anomaly_id, organization_id)` → `anomaly (anomaly_id, organization_id)`. Для этого на аномалии есть `UNIQUE (anomaly_id, organization_id)`. Индекс `notification_org_idx (organization_id, created_at DESC)`.

Оповещение не привязано к одному сотруднику. Его видят администратор и аналитик этой организации. Отдельной отметки прочтения предметная модель не задаёт.

## Что проверяет база, а что — API

PostgreSQL обеспечивает ключи, совпадение организации по цепочке, допустимые коды, обязательность текста, запрет спама без даты и согласованность статуса с полями разбора.

API обеспечивает пароль, код смены пароля, сеанс, роль на каждой операции, разбор CSV, классификацию, поиск похожих текстов, сравнение окна с базовым периодом, перевод предела в решение «открыть аномалию», идемпотентность повторного сохранения и отказ устаревшей версии. Проверка в React это не заменяет.
