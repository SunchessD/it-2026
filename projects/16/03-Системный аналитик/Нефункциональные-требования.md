# Нефункциональные требования

Требования к безопасности, надёжности и производительности сервиса. Показатели нагрузки заданы для приёмочных испытаний.

| ID | Требование | Проверка |
| --- | --- | --- |
| NFR-01 | Любое чтение и изменение расходов и категорий ограничено владельцем из серверной сессии. | Два пользователя, подмена идентификаторов в URL и POST. Чужие данные не выдаются и не изменяются. |
| NFR-02 | Пароли хранит штатный механизм Django в виде хэшей. Сессии хранятся в PostgreSQL, cookie имеют HttpOnly, SameSite=Lax и Secure при HTTPS. Изменения выполняются через POST с CSRF-проверкой. | Проверка настроек, cookie, отсутствия открытых паролей в БД и логах, отклонения POST без CSRF. |
| NFR-03 | Изменение расхода или категории и увеличение ревизии фиксируются одной транзакцией. | Искусственная ошибка перед COMMIT не оставляет частичного изменения. Одновременные записи не теряют увеличения счётчика. |
| NFR-04 | При недоступном Redis операции учёта продолжаются, сводка рассчитывается по PostgreSQL. Тайм-аут соединения и чтения Redis: 200 мс, автоматические повторы отключены. | Остановить Redis и выполнить добавление и просмотр сводки. Итоги совпадают с данными БД. |
| NFR-05 | Целевой 95-й процентиль времени ответа списка и сводки не более 1 с при 20 одновременных пользователях и 100 000 расходах в БД. | Пятиминутный тест на стенде 2 vCPU, 4 ГБ RAM. Отдельно измерить холодный и тёплый кэш, записать долю попаданий и число агрегирующих запросов. |
| NFR-06 | Денежные суммы хранятся и складываются в целых копейках. | Значения 0,10 и 0,20 дают 0,30. Недопустимые суммы и переполнение границы отклоняются. |
| NFR-07 | Интерфейс работает при ширине от 360 до 1440 CSS-пикселей, основные действия доступны с клавиатуры. | Проверка форм, навигации и таблиц в Chrome и Firefox на дату приёмки. На узком экране список преобразуется в карточки. |
| NFR-08 | Ошибки формы указаны у соответствующего поля, введённые значения сохраняются, кроме паролей. Удаление требует подтверждения. | Проверка неверной суммы, даты, категории, повторного названия и отмены удаления. |
| NFR-09 | Резервная копия PostgreSQL создаётся ежедневно, хранятся последние семь копий. Целевые RPO 24 ч и RTO 1 ч. | Восстановить копию в отдельную БД и проверить пользователей, категории, расходы и ревизии. Восстановление кэша не требуется. |
| NFR-10 | Секреты задаются через окружение, PostgreSQL и Redis не доступны из публичной сети. Логи не содержат паролей, cookie, полных комментариев расходов и содержимого сводок. | Проверка конфигурации развёртывания и образцов логов. |
| NFR-11 | TTL сводки составляет 60 с. Начальное ограничение памяти Redis 128 МБ, политика allkeys-lru. Промах и вытеснение считаются обычными состояниями. | Проверить повторное заполнение после TTL и после удаления демонстрационного ключа. При ошибке записи кэша вернуть рассчитанный результат. |
| NFR-12 | Репозиторий содержит воспроизводимую инструкцию запуска, зафиксированные зависимости и миграции БД. | Новый экземпляр приложения запускается по README, миграции применяются на пустую БД. |

## Границы надёжности

Первоначальное развёртывание использует один экземпляр приложения и одну PostgreSQL. Автоматическое переключение на резервный сервер, распределённый Redis Cluster и гарантированный режим работы без основной БД не предусматриваются. Время ответа по NFR-05 измеряется на названном стенде и не является обещанием для любой нагрузки.

Redis хранит только восстанавливаемые сводки. Сессии и исходные расходы от него не зависят. Отказ PostgreSQL должен приводить к явной ошибке операции. Нельзя сообщать об успешном сохранении до COMMIT или подменять ошибку пустым списком.
