# Пользовательские истории

Истории описывают первую версию сервиса. Критерии приёмки используются при проверке реализации.

| ID | История | Критерии приёмки |
| --- | --- | --- |
| US-01 | Как гость, я хочу создать учётную запись, чтобы вести личный учёт. | Свободный логин и допустимый пароль создают аккаунт и начальные категории. Занятый логин, слабый пароль или несовпадение подтверждения оставляют форму с понятной ошибкой. |
| US-02 | Как пользователь, я хочу входить и выходить из сервиса, чтобы доступ к расходам был ограничен моей учётной записью. | Правильные данные открывают список расходов. Неверные данные дают общее сообщение об ошибке входа. После выхода закрытые страницы снова требуют входа. |
| US-03 | Как пользователь, я хочу записать сумму, дату и категорию траты, чтобы не потерять её. | Расход с суммой 80,00 рубля сохраняется как 8 000 копеек. Нулевая, отрицательная сумма и более двух десятичных знаков отклоняются. Чужая или архивная категория для новой записи недоступна. |
| US-04 | Как пользователь, я хочу найти расходы за период и по категории, чтобы проверить отдельные траты. | Фильтры применяются совместно. Обе границы периода включаются. Результат содержит только мои записи. После сброса показаны мои расходы текущего месяца по всем категориям. |
| US-05 | Как пользователь, я хочу исправить ошибочную запись, чтобы итог не искажался. | Изменяются сумма, дата, категория и комментарий. Следующий запрос сводки отражает исправление. Чужая запись не открывается и не изменяется. |
| US-06 | Как пользователь, я хочу удалить лишний расход, чтобы он не попадал в расчёты. | Перед удалением требуется подтверждение. Отмена сохраняет запись. Подтверждение удаляет её и меняет последующие итоги. |
| US-07 | Как пользователь, я хочу создавать и переименовывать категории, чтобы группировать расходы удобным мне способом. | Название содержит 1–50 символов после удаления пробелов по краям. Повтор названия без учёта регистра в моём справочнике отклоняется. Переименование видно и в истории. |
| US-08 | Как пользователь, я хочу архивировать неиспользуемую категорию, чтобы она не мешала вводу новых расходов. | Категория исчезает из выбора для новой записи, но остаётся у старых расходов и в сводках. Восстановление возвращает её в список выбора. |
| US-09 | Как пользователь, я хочу удалить ошибочно созданную пустую категорию. | Пустая категория удаляется после подтверждения. Категория с расходами не удаляется; вместо этого доступно архивирование. |
| US-10 | Как пользователь, я хочу видеть сумму расходов и распределение по категориям за месяц, чтобы понимать структуру трат. | Для 510 + 90 + 120 итог равен 720,00 рубля. Сумма всех категорий совпадает с итогом. Чужие расходы и расходы соседнего месяца исключаются. Пустой месяц показывает 0,00. |
| US-11 | Как пользователь, я хочу получать актуальную сводку после изменения расхода и продолжать работу при отказе кэша. | После добавления 80,00 следующий запрос показывает 800,00. При недоступном Redis результат рассчитывается по PostgreSQL. При недоступной PostgreSQL показывается ошибка, а не нулевой итог. |

## Общие условия доступа

Владельца определяет сервер по сессии. Поле `user_id` от клиента не используется для выбора владельца. Просмотр, изменение, удаление и фильтрация всегда ограничены текущим пользователем. Проверка распространяется и на прямое обращение по URL, а не только на видимые кнопки.

## Проверочный набор

Для пользователя A: «Продукты» 510 и 120 рублей, «Транспорт» 90 рублей в октябре 2026 года. Дополнительно: 200 рублей за сентябрь у A и 999,99 рубля за октябрь у B. Октябрьская сводка A должна включать только 720 рублей. Этот набор связывает требования проекта с демонстрацией Redis.
