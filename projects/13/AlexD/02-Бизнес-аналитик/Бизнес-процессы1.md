## **Бизнес-процессы**

### **Акторы**

- Садовод — зарегистрированный пользователь, ведёт коллекцию растений и расписание ухода

- Новый пользователь — незарегистрированный пользователь, у когорого основные функции приложения не доступны

- Система — серверная часть приложения, отвечает за логику, уведомления, хранение данных

- Администратор — модерирует контент энциклопедии и сообщества

### **Группа 1: Регистрация и профиль**

**БП-1.1: Регистрация нового пользователя**

- Роли: Новый пользователь, Система

- Триггер: Новый пользователь заходит в приложение и инициирует процесс регистрации

- Шаги:
1) Новый пользователь заполняет форму (имя, email, пароль)
2) Валидация данных
3) Система создает неактивную учетную запись в БД (статус pending)
4) Система генерирует уникальный код активации и отправляет письмо с кодом на указанный email
5) Система оповещает пользователя и перенаправляет пользователя на страницу ввода кода активации
6) Пользователь переходит по ссылке на страницу для активации акаунта

- Результат: Учётная запись создана (неактивна), письмо отправлено

**БП-1.2: Активация учетной записи (и первый вход)**

- Роли: Новый пользователь, Система

- Триггер: Пользователь получил письмо и вводит код в приложении

- Шаги:
1) Пользователь вводит код активации из письма
2) Система проверяет корректность кода и срок его действия
3) При успехе: статус учетной записи меняется на active
4) Система автоматически генерирует сессию
5) Перенаправление на дашборд
   
- Результат: Учётная запись активирована, пользователь авторизован

  **БП-1.3: Аутентификация (для последующих входов)**

- Роли: Садовод, Система

- Триггер: Открытие страницы входа (при повторном визите)

- Шаги:

- 1) Ввод email и пароля
-Проверка учётных данных
Генерация сессии
Перенаправление на дашборд
Результат: Пользователь авторизован, сессия активна.

**БП-1.3: Редактирование профиля**

- Роли: Садовод, Система

- Триггер: Открытие раздела «Профиль»

- Шаги: 1) Отображение текущих данных → 2) Изменение полей (имя, аватар, город) → 3) Валидация → 4) Сохранение

- Результат: Профиль обновлён

### **Группа 2: Управление коллекцией растений**

**БП-2.1: Добавление растения в коллекцию**

- Роли: Садовод, Система

- Триггер: Нажатие «Добавить растение»

- Шаги: 1) Выбор вида из энциклопедии или ввод вручную → 2) Загрузка фотографии → 3) Указание местоположения (комната) → 4) Настройка расписания ухода → 5) Сохранение карточки

- Результат: Растение добавлено, расписание ухода активировано

**БП-2.2: Отметка о выполненном уходе**

- Роли: Садовод, Система

- Триггер: Напоминание о поливе / подкормке или ручной вызов

- Шаги: 1) Открытие карточки растения → 2) Нажатие «Полито» / «Подкормлено» / «Пересажено» → 3) Запись в историю ухода → 4) Пересчёт следующей даты

- Результат: Действие зафиксировано, следующее напоминание обновлено

**БП-2.3: Просмотр истории ухода**

- Роли: Садовод, Система

- Триггер: Открытие карточки растения → вкладка «История»

- Шаги: 1) Запрос записей по растению → 2) Отображение хронологии (дата, тип действия, заметки)

- Результат: Пользователь видит полную историю ухода за растением



### **Группа 3: Энциклопедия и сообщество**

**БП-3.1: Поиск растения в энциклопедии**

- Роли: Садовод, Система

- Триггер: Переход в раздел «Энциклопедия»

- Шаги: 1) Ввод названия или выбор категории → 2) Поиск по базе → 3) Отображение карточки растения (описание, условия, фото)

- Результат: Пользователь получает информацию по интересующему виду

**БП-3.2: Публикация записи в сообществе**

- Роли: Садовод, Система, Администратор

- Триггер: Нажатие «Создать запись»

- Шаги: 1) Ввод текста и загрузка фото → 2) Проверка на запрещённый контент → 3) Публикация → 4) Отображение в ленте

- Результат: Запись опубликована, видна другим пользователям

**БП-3.3: Комментирование записи**

- Роли: Садовод, Система

- Триггер: Нажатие «Ответить» под записью

- Шаги: 1) Ввод текста комментария → 2) Сохранение → 3) Уведомление автора записи

- Результат: Комментарий опубликован, автор уведомлён

**БП-3.4: Получение уведомлений**

- Роли: Садовод, Система

- Триггер: Наступление события (время полива, новый комментарий, ответ)

- Шаги: 1) Формирование уведомления → 2) Сохранение в базу → 3) Push/email по настройкам пользователя

- Результат: Пользователь информирован о событии
