# Пример Redis: кэш месячной сводки

Пример показывает чтение из кэша и БД, обновление версии результата, TTL и расчёт из БД при недоступном Redis.

Проверено 09.11.2026 на Linux: Python 3.12.14, Redis 8.10.2, redis-py 6.4.0. Сервер Redis запускался локально без сохранения на диск. Все 9 тестовых методов прошли, вывод `demo.py` совпал с `expected-output.txt`. Запуск контейнера через Docker Compose на этом стенде не проверялся.

## Файлы

- `demo.py` - исходные данные, расчёт, кэш и демонстрационный сценарий.
- `test_demo.py` - интеграционные проверки с настоящим Redis.
- `requirements.txt` - версия Python-клиента.
- `compose.yaml` - настройки локального сервера Redis.
- `expected-output.txt` - сохранённый вывод примера.
- `commands.txt` - команды для redis-cli.

## 1. Запуск Redis

Нужен установленный Docker с Compose. Команды выполняются из папки `src`, где лежит `compose.yaml`:

```bash
docker compose up -d --wait
docker compose exec redis redis-cli ping
```

На вторую команду сервер должен ответить `PONG`. Контейнер работает в фоне. Порт доступен только на `127.0.0.1`, RDB и AOF отключены. При первом запуске Docker скачает образ, поэтому подготовку нужно выполнить заранее.

Для интерактивного ввода команд из `commands.txt`:

```bash
docker compose exec redis redis-cli
```

Выйти из redis-cli можно командой `quit`. После работы остановить и удалить контейнер этого примера:

```bash
docker compose down
```

Если контейнер с именем `yudin-redis-demo` уже запущен старой командой `docker run`, сначала остановите именно его в прежнем терминале через Ctrl+C.

Можно использовать уже установленный локальный Redis. В этом случае Compose не нужен. Варианты установки описаны в [официальном руководстве](https://redis.io/docs/latest/operate/oss_and_stack/install/).

## 2. Python-окружение

Нужен Python 3.10 или новее. Команды также выполняются из `src`.

Windows PowerShell, без активации окружения:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe demo.py
```

macOS / Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python demo.py
```

Для повторного показа достаточно последней команды. Каждый запуск заново создаёт исходные расходы и свой префикс ключей.

## 3. Что показывает программа

1. Первый запрос: DB, сумма 720.00, одна агрегация.
2. Повтор: CACHE, сумма 720.00, число агрегаций остаётся равным 1.
3. После добавления 80.00: DB, сумма 800.00, число агрегаций становится равным 2.
4. Повтор: CACHE, сумма 800.00, число агрегаций остаётся равным 2.
5. При недоступном соединении Redis: DB, сумма 800.00.

Все шаги выполняются автоматически. Последний шаг обращается к зарезервированному локальному порту без сервера и получает настоящий отказ соединения. Работающий Redis при этом не выключается.

Пример удаляет только созданные им ключи. FLUSHDB и FLUSHALL не вызываются.

## 4. Проверки

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_demo.py
```

macOS / Linux:

```bash
.venv/bin/python -m unittest -v test_demo.py
```

Ожидаемый результат: `Ran 9 tests`, затем `OK`. Redis должен быть запущен.

Проверяются попадание и промах, разделение пользователей и месяцев, смена ревизии, переименование категории, истечение TTL, некорректный кэш, отказ соединения, изменение во время расчёта, суммы и принадлежность категории.

## 5. Если порт 6379 занят

Для Compose можно выбрать другой локальный порт. Например, Windows PowerShell:

```powershell
$env:REDIS_DEMO_PORT = "6380"
docker compose up -d --wait
.\.venv\Scripts\python.exe demo.py --redis-url redis://127.0.0.1:6380/0
$env:REDIS_URL = "redis://127.0.0.1:6380/0"
.\.venv\Scripts\python.exe -m unittest -v test_demo.py
```

macOS / Linux:

```bash
REDIS_DEMO_PORT=6380 docker compose up -d --wait
.venv/bin/python demo.py --redis-url redis://127.0.0.1:6380/0
REDIS_URL=redis://127.0.0.1:6380/0 .venv/bin/python -m unittest -v test_demo.py
```

`REDIS_DEMO_PORT` меняет порт контейнера на компьютере. Параметр `--redis-url` задаёт адрес для демонстрации, а `REDIS_URL` - для тестов.

## Границы примера

SQLite хранится в памяти процесса и заполняется при каждом запуске. В ней находятся исходные записи, а в Redis - сериализованная сводка в обычном String. Суммы хранятся целыми копейками.

Счётчик `aggregate_queries` учитывает только агрегирующие запросы. Даже при попадании в кэш программа читает ревизию из БД. Демонстрация не измеряет ускорение.

Ключ включает пользователя, месяц и ревизию. Изменение расхода и увеличение ревизии происходят в одной транзакции SQLite. Это не общая транзакция SQLite и Redis. Уже выполняющийся запрос может вернуть результат, прочитанный до конкурентного изменения. Новые запросы используют новую ревизию.

Аутентификация и веб-интерфейс в этот пример не входят. Django и PostgreSQL на слайде 13 относятся к проектируемому веб-сервису.
