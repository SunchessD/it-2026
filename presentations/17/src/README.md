# Пример Redis: кэш месячной сводки

Пример показывает чтение из кэша и БД, обновление версии результата, TTL и расчёт из БД при недоступном Redis.

Проверено 10.11.2026 на Linux: Python 3.12.14, Redis 8.10.2, redis-py 6.4.0. Все 9 тестовых методов прошли, вывод `demo.py` совпал с `expected-output.txt`. Сервер запускался локально без сохранения на диск. Docker Compose и командный файл Windows на этом стенде не выполнялись.

## Запуск на Windows

### Первая подготовка

1. Установить [Python для Windows](https://www.python.org/downloads/windows/) версии 3.10 или новее. После установки открыть новый терминал и проверить `py --version`. Если команда `py` недоступна, проверить `python --version`.
2. Установить [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/), включить предложенный установщиком WSL 2 и перезагрузить компьютер, если потребуется. Запустить Docker Desktop и дождаться готовности движка. Нужен режим **Linux containers**. Команды ниже выполняются в Windows; отдельную Ubuntu для них устанавливать не требуется.
3. Полностью распаковать архив. Открыть папку `presentations/17/src`, где лежат `compose.yaml` и `run-windows.cmd`. В Проводнике можно ввести `powershell` в адресную строку и нажать Enter.
4. Выполнить проверку:

```powershell
.\run-windows.cmd test
```

Командный файл создаёт локальное окружение `.venv`, при необходимости устанавливает клиент Redis, запускает контейнер и выполняет тесты. Ожидаемый результат: `PONG`, затем `Ran 9 tests` и `OK`. Первый запуск требует интернета для скачивания образа и Python-пакета; его нужно выполнить заранее.

Проверки охватывают попадание и промах, разделение пользователей и месяцев, смену ревизии, переименование категории, истечение TTL, некорректный кэш, отказ соединения, изменение во время расчёта, суммы и принадлежность категории.

### Показ примера

Открыть Docker Desktop, затем из той же папки выполнить:

```powershell
.\run-windows.cmd demo
```

Можно также дважды щёлкнуть `run-windows.cmd` в Проводнике. В этом случае окно останется открытым после завершения. Окружение активировать не нужно, политика выполнения PowerShell не меняется.

После успешной первой подготовки повторный запуск использует установленные зависимости и сохранённый образ Docker. Для репетиции стоит один раз повторить показ с отключённым интернетом. На самом показе загрузки и установки выполнять не потребуется, если окружение и образ сохранились.

### Что показывает программа

1. Первый запрос: DB, сумма 720.00, одна агрегация.
2. Повтор: CACHE, сумма 720.00, число агрегаций остаётся равным 1.
3. После добавления 80.00: DB, сумма 800.00, число агрегаций становится равным 2.
4. Повтор: CACHE, сумма 800.00, число агрегаций остаётся равным 2.
5. При недоступном соединении Redis: DB, сумма 800.00.

Все шаги выполняются автоматически. Каждый запуск заново создаёт исходные расходы и свой префикс ключей. Последний шаг обращается к зарезервированному локальному порту без сервера и получает настоящий отказ соединения. Работающий Redis при этом не выключается.

Пример удаляет только созданные им ключи. FLUSHDB и FLUSHALL не вызываются.

### Команды Redis и остановка

Для интерактивного ввода команд из `commands.txt`:

```powershell
docker compose exec redis redis-cli
```

В файле есть SET, GET, TTL, DEL и пример атомарного увеличения: два INCR меняют 10 на 12. Выйти из redis-cli можно командой `quit`.

После работы остановить и удалить контейнер этого примера:

```powershell
docker compose down
```

Порт Redis доступен только на `127.0.0.1`. RDB и AOF отключены: данные этого учебного контейнера сохранять не требуется.

### Если возникла ошибка

| Сообщение или ситуация | Действие |
| --- | --- |
| Python не найден | Проверить `py --version` или `python --version`; после установки открыть новый терминал. |
| Локальное `.venv` не запускается | Если папку переносили с другого компьютера или из другой ОС, удалить только `.venv` внутри `src` и повторить запуск. |
| Docker не найден | Установить Docker Desktop и открыть новый терминал. |
| Docker engine недоступен | Запустить Docker Desktop и дождаться готовности. |
| Требуется Linux containers | Переключить Docker Desktop в этот режим. |
| Не скачался образ или пакет | Проверить интернет и повторить подготовку до выступления. |
| Имя `yudin-redis-demo` уже занято | Проверить контейнер в Docker Desktop. Если это прежний контейнер данного примера, остановить и удалить его, затем повторить запуск. |
| Порт 6379 занят | Выбрать другой порт командами ниже. |

Другой локальный порт, например 6380, задаётся в PowerShell:

```powershell
$env:REDIS_DEMO_PORT = "6380"
.\run-windows.cmd test
.\run-windows.cmd demo
```

Командный файл передаст этот порт контейнеру, демонстрации и тестам. Переменная действует в текущем окне PowerShell; в новом окне её нужно задать снова. Исходные файлы менять не требуется.

## Ручной запуск на Windows

Те же действия без командного файла, из `src`:

```powershell
docker compose up -d --wait
docker compose exec redis redis-cli ping
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe demo.py
.\.venv\Scripts\python.exe -m unittest -v test_demo.py
```

Если используется порт 6380, демонстрации нужен аргумент `--redis-url redis://127.0.0.1:6380/0`, а тестам — переменная `$env:REDIS_URL = "redis://127.0.0.1:6380/0"`.

## macOS / Linux

```bash
docker compose up -d --wait
docker compose exec redis redis-cli ping
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python demo.py
.venv/bin/python -m unittest -v test_demo.py
```

Можно использовать уже установленный локальный Redis. Тогда Compose не нужен. [Варианты установки Redis](https://redis.io/docs/latest/operate/oss_and_stack/install/).

Для другого порта:

```bash
REDIS_DEMO_PORT=6380 docker compose up -d --wait
.venv/bin/python demo.py --redis-url redis://127.0.0.1:6380/0
REDIS_URL=redis://127.0.0.1:6380/0 .venv/bin/python -m unittest -v test_demo.py
```

## Файлы

- `demo.py` — исходные данные, расчёт, кэш и демонстрационный сценарий.
- `test_demo.py` — интеграционные проверки с настоящим Redis.
- `run-windows.cmd` — подготовка и запуск на Windows.
- `requirements.txt` — версия Python-клиента.
- `compose.yaml` — настройки локального сервера Redis.
- `expected-output.txt` — сохранённый вывод примера.
- `commands.txt` — команды для redis-cli.

## Границы примера

SQLite хранится в памяти процесса и заполняется при каждом запуске. В ней находятся исходные записи, а в Redis - сериализованная сводка в обычном String. Суммы хранятся целыми копейками.

Счётчик `aggregate_queries` учитывает только агрегирующие запросы. Даже при попадании в кэш программа читает ревизию из БД. Демонстрация не измеряет ускорение.

Ключ включает пользователя, месяц и ревизию. Изменение расхода и увеличение ревизии происходят в одной транзакции SQLite. Это не общая транзакция SQLite и Redis. Уже выполняющийся запрос может вернуть результат, прочитанный до конкурентного изменения. Новые запросы используют новую ревизию.

Аутентификация и веб-интерфейс в этот пример не входят. Django и PostgreSQL на слайде 16 относятся к проектируемому веб-сервису.
